# Draw the launcher icon and the picker preview as vectors, not with the renderer

The launcher icon and the widget picker's preview are both pictures of the Dial,
and the Dial already has a renderer. The obvious move is to draw them with it,
so that they and the thing they stand for cannot drift apart. Neither can be.

`renderDial` draws on an Android `Canvas` and hands back a `Bitmap`, so running
it needs a device or an emulator. Nothing in this project's build has either:
the tests are JVM tests and the release build is Gradle and `d8`. Generating the
icon from it would mean an instrumented test writing PNGs, checked in, and
regenerated by hand whenever the Dial changed — a worse bond than none, because
it would look automatic while being manual.

The preview is stopped by the same thing plus one more: the picker asks for it
before there is a widget, so there is no size, no Event, and nothing to render.

So both are hand-drawn vectors. Vectors rather than PNGs because there is then
one drawing instead of one per density bucket, and because `minSdk` is 26, which
is where adaptive icons arrived — there is nothing older to keep a bitmap for.

What the renderer and the drawings share is held by `IconTest` rather than by
generation:

- The colours are read from `Accent`, `DialColours` and `trackColour`, so a
  changed Accent or a changed disc leaves the test naming the file that has
  fallen behind.
- The preview's proportions are read from `dialLayout(108, ...)` — the disc's
  radius, the arc's radius and its stroke, and that the arc starts at twelve
  o'clock. `dialLayout` touches no Android, so the same maths the renderer obeys
  can be checked against an XML file on the JVM. The picker cannot promise a
  shape the widget does not draw.

Neither drawing can be judged by a test, so both were rasterised and looked at:
the two icon layers under a circular and a squircle mask at 48px, which is the
size a launcher draws, and the preview at the size the picker shows. Nothing in
the build does that, so it has to be done again by hand whenever either changes.

## Consequences

- The launcher icon is not held to the Dial's proportions, only to its colours.
  It cannot be: the foreground has to stay inside the adaptive icon's 66-unit
  safe zone, so the arc sits inside the rim rather than on it, and it is drawn a
  shade heavier because a faithful stroke is a hairline at 48dp. `IconTest`
  checks the safe zone instead.
- A vector drawable has no text, so the number on both is a path. It is one
  digit — two are unreadable at launcher size — and the label under it and the
  Event's title are left out rather than drawn glyph by glyph.
- Anything about the Dial the tests do not name can still drift. That is the
  price of not generating them, and it is why the tests name as much as they do.
